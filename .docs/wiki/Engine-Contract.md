# Engine contract

## Engine protocol

Long-lived executable reads one UTF-8 JSON request per line, writes exactly one JSON response per line. Request: `{"id":1,"method":"board.get","params":{"board_id":"id"}}`. Success: `{"id":1,"result":{"board":{},"can_undo":false,"can_redo":false}}`. Failure: `{"id":1,"error":{"code":"invalid_command","message":"explanation"}}`. Logs go to stderr. No UI or filesystem dependencies in Rust library. Methods: board.create (id, title), board.open (board), board.get (board_id), board.apply (board_id, command), board.undo, board.redo, board.close. Create/open/apply/history return state envelope.

## Board

Board: id:string, title:string, version:1, revision:integer, items:Item[], connections:Connection[], viewport:{x:number,y:number,zoom:number}, background:string. Extra serde defaults accepted when opening old boards. Item: id:string, kind:image|note|document|swatch|link|board|column|todo|shape|stroke|file, x/y/width/height numbers, rotation:number degrees, z:number, opacity:number, locked:boolean, hidden:boolean, group_id:string|null, parent_id:string|null, title:string, text:string, color:string, asset_id:string|null, url:string, data:object. Image data: flip_x/flip_y boolean, grayscale boolean, crop:{x,y,width,height} normalized source fractions, sampling:string. Todo data checked:boolean. Any item may carry data.comments: at most 200 of {id: identifier, text: 1 to 4000 characters, author: at most 80, at: epoch milliseconds, resolved?: boolean}. The engine merges an update's data into the existing data one level deep, so clear a list by writing []. settings.labels is a list of at most 32 {id, name (1 to 40 characters), color #RRGGBB} with unique ids; items refer to them in data.labels (at most 12 ids, each defined). A settings command that drops a label also removes it from every item in the same step. Item kind table carries data.table {columns: 1 to 26 of {name up to 60 characters, type text|number|currency|percent|date|checkbox}, rows: up to 500 arrays of at most one cell per column, each cell text up to 2000 characters}; formulas are cell text starting with = and are evaluated by the frontend, so exports carry them as written. File items with data.mime video/* or audio/* play in place, with data.autoplay and data.loop booleans; an uploaded file only gets a video or audio type when its leading bytes match the container. GET /api/assets/{id} serves video and audio inline and answers single byte ranges with 206. GET /api/boards/{id}/items/{item}/export?format=md|txt|docx|pdf returns one note or document card as a download, laid out with the same Markdown subset as the board. Board card data board_id:string. Stroke data points:[{x,y}], stroke_width:number. Shape data shape:rect|ellipse|line, fill:string. Connections: id:string, from:string, to:string, label:string, color:string. Data supports future extension kinds while core geometry remains validated. Swatch canonical colors, note/document source formats, safe bounded Markdown, original-pixel sampling and conditional saves are validated in native/formref-core/src/model.rs and backend/app/core/.

Boards also include validated, backwards-compatible `settings` for grid visibility, grid size, snapping and canvas grayscale preview. The `settings` and `snap` commands and optional `distribute.gap` are listed under Commands below and explained in [Canvas](Canvas.md). Preview grayscale does not change original media or imply grayscale exports.

## Commands

- add: items array; remove: ids array; update: ids array, patch object.
- transform: ids, dx/dy defaults 0, scale default 1, rotation default 0; pivot optional x/y. Scaling/rotation around collective center when absent.
- duplicate: ids, synced optional boolean; engine generates collision-free IDs and offsets by 24. A plain duplicate drops data.sync_id; with synced true, note and document copies share the source's data.sync_id (created if missing), and any update that changes title, text, color, data.text_format or data.font on one of them applies the same values to every unlocked item with that sync_id in the same step.
- align: ids, mode:left|right|top|bottom|center_x|center_y.
- distribute: ids, axis:x|y. pack: ids, gap default 24, columns optional integer. normalize: ids, mode:width|height|area, value positive.
- group: ids, group_id optional string; ungroup: ids. order: ids, mode:front|back|forward|backward. Locked items reject mutating commands except update locked false.
- connect: connection object. disconnect: ids. viewport: viewport object. rename: title. background: color.
- settings: patch of grid_visible, grid_size (4 to 512), snap_enabled, grayscale, labels, and window (v0.7.3: the desktop window this board opens in, {x, y (-100000 to 100000), width, height (200 to 20000, logical pixels), always_on_top, opacity (0.2 to 1)}, or null to forget it; omitted from saved boards when unset), and searches (v0.10.0: at most 24 saved searches, the whole list replaced by a patch, each {id (unique), name (1 to 60 bytes), text? (up to 200 bytes), kind? (an item kind), color? (#RRGGBB), tolerance? (1 to 100), similar? {item_id, level close|related|loose}, tags? (v0.11.0: at most 12, nonempty, up to 60 bytes, matched ignoring case against data.tags), labels? (at most 12 label ids matched against data.labels), rating? (v0.22.0: 0 keeps unrated pictures, 1 to 5 keeps pictures with at least that many stars)} with at least one of text, kind, color, similar, tags, labels or rating; omitted from saved boards while empty; a similar item that no longer exists is kept and the window skips it; searches for all boards are not board state, see below). snap: ids, grid_size optional.

Searches for all boards (v0.16.0) are kept by the service, not the engine, in `searches.json` in the data folder: `GET /api/searches` returns `{searches}` and `PUT /api/searches` replaces the whole list. At most 48, each `{id (letters, digits, - or _), name (1 to 60 bytes, unique ignoring case), text?, kind?, color? (#RRGGBB), tolerance? (1 to 100), tags? (at most 12, up to 60 bytes), label_names? (at most 12, up to 40 bytes), rating? (v0.22.0: 0 to 5, as for board searches)}` with at least one of text, kind, color, tags, label names or rating; unknown fields are refused, so a similar picture cannot be stored. The window turns label names into this board's label ids ignoring case and leaves out names the board does not have. There is no undo for this list.

The practice log (v0.18.0) is also service state, in `practice.json`: `GET /api/practice` returns `{sessions}`, and `POST /api/practice` with `{board_id?, board_title?, pictures (1 to 10000), seconds_each (0 to 3600), drawing_seconds (0 to 86400), plan? (v0.19.0: lowercase letters and digits, up to 24, such as warmup, class30, class60)}` appends one entry stamped with `at` (Unix seconds); unknown fields are refused and only the last 500 entries are kept. `DELETE /api/practice` (v0.20.0) empties the log.
- rotate: ids, degrees default 90 (-360 to 360), each root about its own centre. opacity: ids, value 0 to 1.
- image: ids (images only), toggle array of flip_x|flip_y|grayscale and/or set {flip_x, flip_y, grayscale, sampling: smooth|nearest, rating: 0 to 5 (v0.22.0; stored as data.rating 1 to 5, 0 removes it)}.
- crop: ids (images only), rect {x, y, width, height} normalised to the source and fitting inside it, or reset true.
- sort: ids (at least 2 roots), key filename|aspect|similarity|color, gap default 24, descending optional; places the result in a grid like pack. Similarity reads data.features (at most 512 numbers); the service fills it from original pixels first. Color reads data.color_order (a finite number; items without one go last in their original order); the service refreshes it from each picture first: the hue angle of the most common clearly coloured part, or 360 plus darkness for black, white and grey pictures. GET /api/boards/{id}/colors?color=#rrggbb&tolerance=1..100 (default 20, a CIEDE2000 difference) returns {color, tolerance, matches: [{id, score}]} best first: swatches within tolerance score 1, pictures score the share of their main colours within tolerance and count from 0.03; it changes nothing. GET /api/boards/{id}/items/{item}/similar?level=close|related|loose (default related) returns {item_id, level, threshold, matches, scores}: scores lists every other visible picture best first with a likeness from 0 to 1, matches those at or above 0.82, 0.7 or 0.58; a non-picture gives 422, a missing item 404; it changes nothing.
- batch: commands array, one atomic undo step. Validate complete command on cloned document before replacing live state. 100 undo entries; unchanged or failed commands never create history.

## HTTP

GET /api/health. GET /api/boards => board summaries. POST /api/boards {title} => state. GET /api/boards/{id} => state. POST /api/boards/{id}/commands {command, expected_revision?} => state; the optional nonnegative integer is compared under the store lock, and a mismatch returns 409 with unchanged state, disk and history. POST /api/boards/{id}/undo and /redo => state. DELETE /api/boards/{id}. POST /api/boards/{id}/duplicate. POST /api/assets multipart file => {id,url,width,height,name,mime,size}. GET /api/assets/{asset_id} bytes. GET /api/boards/{id}/items/{item_id}/sample?u=&v= => source-pixel result; finite normalized coordinates must be within 0..1, and sampling adds no revision/history. POST /api/import multipart file supports portable .formref zip or .istack JSON and maps into a new board. GET /api/boards/{id}/export?format=portable|json|png|svg|markdown returns a downloadable file. GET /api/boards/{id}/events SSE sends revision events from HTTP/MCP mutations. Static frontend production is served at /. GET and PUT /api/session {open, active} store the open board tabs. GET and PUT /api/preferences {keys: {command_id: [combo]}} store shortcut overrides (at most 4 combos per command, combos like mod+shift+k). DELETE /api/boards/{id} moves the board to the trash. GET /api/trash?board_id= lists {boards, items}; POST /api/trash/boards/{id}/restore and DELETE /api/trash/boards/{id}; POST /api/trash/items/{board_id}/{entry_id}/restore returns state (one undo step) and DELETE removes the entry; DELETE /api/trash empties everything. POST /api/boards/{id}/items/{item}/comments {text, author?} adds a comment (author defaults to Agent when X-FormRef-Client is sent, otherwise You); POST .../comments/{comment}/resolve {resolved} and DELETE .../comments/{comment}; each is one guarded update and returns state. GET /api/templates lists built-in and saved templates; POST /api/templates {board_id, title, description?} saves one; POST /api/templates/{id}/use {title?} returns the new board's state; DELETE /api/templates/{id} removes a saved template. POST /api/capture {url} fetches a public http or https address (each hop is resolved once and the connection goes to that checked address, with the original Host and TLS server name, so a changing DNS answer cannot redirect it; each redirect hop is re-checked; loopback, private, link-local and reserved addresses are refused unless FORMREF_CAPTURE_ALLOW_PRIVATE=1) and returns {asset, url} for an image or other file, or {page, images} with up to 60 image addresses found in img, srcset, og:image and image_src. GET /api/agent/runners, GET and POST /api/agent/settings, POST /api/agent/turns {board_id, message, runner} streams start, text, tool, tool_result, error and done events; POST /api/agent/turns/{id}/stop and /undo. A mutating request carrying X-FormRef-Client is refused with 403 outside_agents_off unless it carries a live turn token or outside agents are allowed; the board's SSE stream then sends a consent event. During a panel turn, a remove command, a board DELETE, or a transform, pack, sort, distribute, align, snap or normalize over 10 or more ids waits for the person: the turn stream sends confirm {id, summary, seconds}, POST /api/agent/confirm/{id} {allow, whole_turn} answers it, and a decline or five minutes without an answer returns 403 declined with nothing changed. The agent setting confirm_changes (default true) turns this off. The PNG export also returns X-FormRef-Left and X-FormRef-Top, the world origin of the picture. API errors have a detail string. All writes auto-persist atomically. API origin is loopback; assets use registered identifiers, never arbitrary filesystem paths.

## Frontend

API client resolves relative /api in Vite via proxy and production FastAPI. Stable item DOM keyed by id, keeps mounted inputs and chrome. Gestures preview CSS transforms then commit final engine command; serialize commands, never replace live panel containers. Frontend owns selection and transient camera but commits camera with viewport command. Inspector inputs commit update. Every command, its label, icon and keys come from frontend/src/app/commands.ts; the right-click menu, palette, keyboard and shortcut sheet (?) all read it, so see [Shell](Shell.md) or press ? for the current keys. Space/middle drag pan, wheel anchored zoom, marquee selection, resize and rotate handles.

## MCP

Use official Python SDK, stdio transport as actual MCP server. Tools call the same store/core service via loopback API to share visible board state. SDK discovery on 2026-10-11 returned 35 tools: remove_background (plain or model method, SAM 2.1 points mapped through crop and flip, or restores the kept original), list_background_models, download_background_model, create_table, capture_from_web, define_labels, label_items, add_comment, resolve_comment, list_templates, create_board_from_template, list_trash, restore_from_trash, list_boards, create_board, get_board, get_board_image (the whole board as a PNG of at most max_edge pixels, plus the world rectangle it covers), add_items, update_items, arrange_items (now with sort), adjust_items (rotate, opacity, image, crop), transform_items, remove_items, undo, redo, import_asset, export_board, search_items, connect_items, configure_canvas, snap_items, sample_image, create_swatch, create_document and set_formatted_text. Resources formref://boards and formref://board/{board_id}. Prompt organize_references. Client config runs root formref mcp. Errors are explicit, never success envelopes for missing boards. Tool mutations cause persisted revision and SSE; sample_image is read-only and returns original source coordinates/RGBA/RGB/HSV/HEX. Formatted updates preserve other item data and use the same revision guard. Canvas settings, snap, swatches and formatted text follow the command list above and the validation in native/formref-core/src/model.rs.
